  一、系统定位
  
  本地知识图谱重构
  Agent，将原始输入、历史对话、代码事实沉淀为可检索、可链接、可衰减的
  Obsidian Wiki。不是通用助理，只做三件事：

  1. _inbox/ 原始材料 → 结构化知识
  2. MemPalace 挖掘对话记忆 → 可复用结论
  3. 输出统一写入 wiki/，维护双向链接 + 记忆权重

  5.1 BM25 检索引擎（bm25_search.py，226行）

  索引 Cache 机制
  - 存储路径：_inbox/.bm25_cache.pkl
  - 结构：{mtimes: {path: float}, doc_paths: [...], corpus: [[tokens], 
  ...]}
  - 重建触发条件：Cache 不存在 / 文件集合变化 / 任意文件 mtime 变化
  - 分词：jieba 中文分词，剥 frontmatter + HTML注释 + Markdown符号后分词
  - aliases 注入：分词前调用 utils.extract_aliases() 提取别名追加到 token
  流末尾
  
  评分公式
  final_score = BM25Okapi_score × current_weight

  检索范围路由
  - --project <name>：global_concepts/ + project_exclusives/<name>/
  - 无参数：全库所有目录

  5.2 上下文脱水管道（context_dehydrator.py，274行）
  
  两种模式

  ┌──────┬──────────────────────┬───────────────────────────────────┐
  │ 模式 │       触发条件       │               行为                │
  ├──────┼──────────────────────┼───────────────────────────────────┤
  │ summ │ BM25路径 / alias命中 │ 剥 frontmatter +                  │
  │ ary  │ （lineno=0）/        │ 去噪，保留完整正文                │
  │      │ hit_lines=[]         │                                   │
  ├──────┼──────────────────────┼───────────────────────────────────┤
  │ prec │ rg路径，有真实行号（ │ 精准裁剪：命中行所在段落，保留代  │
  │ ise  │ lineno>0）           │ 码块整体，附面包屑                │
  └──────┴──────────────────────┴───────────────────────────────────┘

  精准裁剪算法（precise 模式）
  1. _build_hierarchy_map(lines)：扫全文建立每行对应的 H1/H2/H3 层级快照
  2. _find_code_block_ranges(lines)：检测代码块范围（支持未闭合块）
  3. 对每个命中行：
    - 若在代码块内 → 整个代码块全保留
    - 否则 → 向上找最近 # 标题，向下找下一 # 标题，整段保留
  4. _protect_links → 处理 → _restore_links：保护 [[双链]] 不被处理打碎
  5. 面包屑格式：[📍 Context Scope: stem ➔ H1 ➔ H2]

  assemble_final_context
  - 按 score 降序排列多文档
  - token 估算：len(text) / 3.5（中英混合）
  - 超预算时：首个文档截断保留（不丢弃），后续文档附警告截断
  - 文档间分隔：=== SOURCE_DOCUMENT_BORDER ===

  5.3 热记忆双轨刷新（hot_refresh.py，203行）
  
  双轨路由

  ┌────────┬───────────────────────┬───────────────────────────┬─────┐
  │  轨道  │       扫描目录        │         输出文件          │ TOP │
  │        │                       │                           │ _N  │
  ├────────┼───────────────────────┼───────────────────────────┼─────┤
  │ --glob │ wiki/global_concepts/ │ wiki/global_hot.md        │ 8   │
  │ al     │                       │                           │     │
  ├────────┼───────────────────────┼───────────────────────────┼─────┤
  │ --proj │ wiki/project_exclusiv │ wiki/project_exclusives/< │     │
  │ ect    │ es/<name>/            │ name>/hot.md              │ 20  │
  │ <name> │                       │                           │     │
  └────────┴───────────────────────┴───────────────────────────┴─────┘

  排序依据：(current_weight, access_count) 降序

  原子写入：fcntl.LOCK_EX 独占锁，超时 10s 抛出异常，防止并发写冲突

  hot_watcher.sh 路由
  wiki/global_concepts/      → hot_refresh.py --global
  wiki/project_exclusives/<N>/ → hot_refresh.py --project <N>
  其他路径                    → 跳过
  冷却时间 2s，排除 hot.md 自身变化（防刷新死循环），异步调用（&）。

  5.4 记忆权重公式（memory_manager.py，143行）
  
  decay_factor = 2^(-(days_passed / 30))           # 半衰期30天
  frequency_bonus = 1.0 + 0.2 * ln(max(1, access_count))  # 频率奖励
  new_weight = initial_weight × decay_factor × frequency_bonus

  关键修复：max(1, access_count) 防止 access_count=0 时 ln(0) = -∞
  导致冷启动负无穷 bug。

  归档阈值：new_weight < 0.15 → 触发 archive_with_backlink_update()

  5.5 Git 同步（vault_sync.sh，78行）
  
  - 分支锁：当前分支必须 = SYNC_BRANCH（默认 main，可 env var 覆盖）
  - 锁等待：通过 fcntl.flock 检查所有 _inbox/.hot_refresh*.lock，等待
  hot_refresh 写入完成，超时 10s 中止
  - 策略：git rebase 保持直线提交史，--force-with-lease 推送

  5.6 精准正文检索（rg_body_search.py，99行）
  
  - 剥离 frontmatter 后逐行 re.search(pattern, line, IGNORECASE)
  - aliases 虚拟行追加（lineno=0），供 context_dehydrator 识别为 alias
  命中 → 降级为 summary 模式
  - frontmatter 行数偏移修正：真实行号 = 正文行号 + frontmatter 行数

  六、Frontmatter Schema
  
  ---
  type: concept
  created_at: 2026-06-01
  last_modified: 2026-06-01
  project: global | <项目名>
  aliases: [别名A, 别名B]          # 增强检索容错，注入 BM25/rg token 流
  code_symbols: []                 # 关联函数/类/模块
  initial_weight: 1.0              # 初始权威度（0.1~1.0）
  current_weight: 1.0              # 由 memory_manager 更新
  last_activated: 2026-06-01       # brain-query 命中时刷新
  access_count: 1                  # 累计检索/引用/更新次数
  ---

  每次 /brain-query 命中后必须回写：last_activated、last_modified →
  今天，access_count +1。
